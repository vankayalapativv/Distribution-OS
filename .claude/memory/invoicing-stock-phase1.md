New capability being built on SA (started 2026-10-31): generate GST invoices in-system + a multi-godown stock ledger; GST reports (GSTR-1) are a later phase. Design doc: `docs/INVOICING-STOCK-ARCHITECTURE.md`.

**Locked decisions:** 18% GST on all oils (CGST9+SGST9 intra-Telangana, IGST18 inter-state; rate stored per line) · one gap-free invoice series per financial year (`SA/2026-27/00001`, resets 1 Apr) · **hard-block** on short stock · opening stock via CSV import + a screen · counter/B2C sales common (standalone no-order invoices; no-GSTIN Telangana buyer = intra) · PDF = clean GST layout rendered client-side → R2. Chosen UX: **New Invoice = single-page (A)**, **Stock Journal = tabs (A)**. UX prototype artifact: Design canvas "SA Invoicing & Stock — UX".

**Key design:** SKUs are the EXISTING catalogue — `products(id) × product_packs.pack_size_litres`, no new SKU master. Stock = append-only `stock_movements` ledger (signed qty) + a rebuildable `stock_balances` cache (non-negative CHECK is the hard-block backstop); every write posts ledger+balance in one `sql.transaction` batch. Invoices: existing `invoices` table EXTENDED (location_id, series_id, supply_type, cgst/sgst/igst, round_off, doc_status, cancel fields) + new structured `invoice_items` (generated invoices); uploaded/parsed invoices keep `line_items` jsonb + `invoice_source`. Invoice number allocated atomically from `invoice_series` (find-or-create FY row, `update … returning next_seq-1`). Cancel reverses stock + re-opens linked order (invoice_line_allocations + recomputeOrderFulfillment).
